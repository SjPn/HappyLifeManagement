## Что уже сильное (относительно ниши)

1. **Сообщество:** доска, форум с аудиторией (владельцы/арендаторы), конфиденциальные обращения с чёткой политикой (автор только у модератора).
2. **Голосования** с аудиторией и ролями — редкость в простых чатах посёлка.
3. **i18n** uk / ru / en — актуально для Украины.
4. **UX-дискipline:** компактные списки + модалки, архив заявок, убраны дубли навигации, бейджи «новое».
5. **Стек:** Next.js 16, React 19, Prisma, Postgres (Neon), Auth.js — нормальная база для роста.

## Где мы слабее ДАХ и аналогов

[ДАХ](https://dah.in.ua/) и похожие (**ОСББ онлайн**, **Miisoft/Дах**, решения для УК) заточены под **финансы и compliance**:

| Возможность | ДАХ / рынок | Happy Life (сейчас) |
|-------------|-------------|---------------------|
| Квитанции, ЕРЦ, банк | ✓ часто | ✗ ручной ввод сумм головой |
| Онлайн-оплата | ✓ | ✗ |
| Бухгалтерия, реестр должников | ✓ | ✗ (только `balanceUah` + месячный биллинг по дому) |
| Загальні збори, е-підпис | ✓ | ✗ (опросы без юр. силы) |
| Мобильное приложение (stores) | ✓ | PWA/браузер |
| Push / SMS рассылки | ✓ | ✗ |
| Мульти-ОСББ / SaaS | ✓ | ✗ один инстанс |
| Масштаб (тысячи ОСББ) | ✓ | пилот 1 КГ |

**Вывод:** конкурировать с ДАХ в **«Финансы»** и **«Бухгалтерия»** на текущем этапе бессмысленно. Имеет смысл **не дублировать** их, а усиливать **коммуникацию, прозрачность заявок, голосования, соседский слой** — там мессенджеры и Excel обычно слабее.

## Сравнение с зарубежными HOA-приложениями

(HeyNeighbor, NeighborCloud, WeNeighbors и др.)

- У них сильнее **календарь, события, push, иногда оплата**.
- У Happy Life сильнее **структура ролей (голова/модератор/арендатор)** и **локальный контекст UA** без vendor lock-in на чужой SaaS.
- Общий разрыв: **нет нативного app и push** — для ежедневного «привыкания» это минус.

## Качество разработки (технический взгляд)

**Плюсы**

- App Router, server actions, `next-intl`, единые компоненты (`Ui`, панели).
- Роли и аудитория вынесены в `lib/audience.ts`, биллинг в `lib/billing.ts`.
- Сборка проходит; линт настроен.

**Минусы / риски**

- Нет автотестов (e2e/unit) в репозитории.
- `prisma db push` вместо миграций — риск на проде при команде >1.
- Фото в `public/uploads/` на Vercel — ненадёжно.
- Single-tenant: нельзя продать «второму посёлку» без форка БД.
- После смены статуса заявки в модалке список обновляется только после refresh (нет `router.refresh`).

## Юзабилити (житель / голова)

**Житель**

- Понятные 4 таба, главная как хаб.
- Платежи простые, но без «оплатить кнопкой» — слабее ожиданий от ДАХ.
- Заявки: короткий список + детали по клику — **хорошо для телефона**.

**Голова**

- Управление с главной, публикации на дашборде — меньше «провалов» в админку.
- Пользователи и заявки в том же паттерне список/модалка — **консистентно**.
- Нет массовых операций, отчётов PDF, экспорта в 1С.

**Модератор**

- Упрощённый дашборд, без лишних разделов — логично.

## Рекомендуемая стратегия (не код)

1. **Пилот в одном КГ** — собрать обратную связь по заявкам, голосованиям, платежам (достаточно ли ручного биллинга).
2. **Не гнаться за паритетом ДАХ** до явного запроса на финансы/оплату.
3. **Следующие усиления UX:** `router.refresh` после действий в модалках; копирование начислений месяца; S3 для фото; опционально Web Push.
4. **Если SaaS:** `Community` + `communityId` + онбординг (см. бэклог).
