| Увидеть начисления / долг | ~ ручной биллинг по дому, без квитанции | ✓✓ сильная сторона ДАХ |

| Показания счётчиков | ✗ (убрано; голова вносит суммы) | ✓ |

**Итог по жителю:** закрывает **коммуникацию и прозрачность процессов** лучше, чем «чат в Viber»; **не закрывает деньги и юридически значимые документы**.

## Сравнение с зарубежными HOA-приложениями

(HeyNeighbor, NeighborCloud, WeNeighbors)

- У них сильнее **календарь, события, push, иногда оплата**.
- У Happy Life сильнее **роли (голова/модератор/арендатор)**, **UA i18n**, **multi-tenant без чужого vendor lock-in**.
- Общий разрыв: **нет нативного app и push** — ниже «привычка открывать каждый день».

## Качество разработки

**Плюсы**

- Next.js 16 App Router, server actions, типизированный Prisma.
- Multi-tenant с первого класса (`communityId`, platform panel).
- Защита от случайного удаления (invite-код), модерация поселков.
- `prisma migrate deploy` на Vercel; CI/e2e зачатки.
- Консистентный UX (список + модалка).

**Минусы / риски**

- Uploads на Vercel эфемерны.
- Нет Web Push / email-дайджестов по заявкам.
- E2E не покрывает весь multi-tenant / platform flow.
- Удаление председателя без автозамены — операционный риск.

## Юзабилити

**Житель:** понятный вход по коду; ожидание апрува головы — норма для КГ, но без push легко забыть зайти. Платежи — «информативно», не «как банк».

**Голова:** хаб управления, биллинг на `/payments`, смена invite-кода в профиле — **практично для пилота**. Нет массового импорта домов из Excel.

**Суперадмин:** компактная панель поселков + председатели; опасные действия с кодом — безопасно, но требует дисциплины (хранить коды).

**Модератор:** узкий фокус — хорошо для конфликта интересов с председателем.

## Скорость развития (команда / продукт)

За короткий период (май 2026): multi-tenant, platform admin, approval flow, invite security, chair management, direct messages, CI/tests skeleton — **высокая скорость итераций** для малой команды. Ограничитель — не железо, а **приоритеты** (финансы vs коммуникация).

## Рекомендуемая стратегия

1. **Пилот 1–3 КГ** — метрики: доля жителей с аккаунтом, заявки/мес, участие в голосованиях.
2. **Не дублировать ДАХ** до запроса на эквайринг/квитанции; можно интеграция «ссылка на оплату» позже.
3. **Ближайший UX:** push или email при смене статуса заявки; S3 для фото; копирование начислений месяца.
4. **SaaS-продажа:** акцент «посёлок за день» + модерация платформы + invite-коды.
