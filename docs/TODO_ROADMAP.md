## Фаза 1: дизайн и UX

- [ ] Собрать **CJM** для жителя и для председателя (ключевые экраны и боли).
- [ ] Прототип **нижней навигации** (согласовать 4–5 табов vs «6 табов» из DOC — избежать дублирования «голосования / чат»).
- [ ] Мобильный **first** wireframe: главная, заявки, голосования, сообщество (доска + чат).
- [ ] Редакционный гайд: **типографика, пустые состояния**, язык уведомлений.

## Фаза 2: архитектура (без кода в первой итерации — только решения)

- [ ] Выбрать стек (например: веб-фреймворк, БД, хранилище файлов, очередь уведомлений).
- [ ] Модель данных: пользователь, участок/дом, роль, заявка, голосование, пост, тема чата, анонимное обращение.
- [ ] Стратегия **фото и геометок**: приватность соседей, ретенция.
- [ ] Очередь уведомлений: email → затем push (отдельная задача).

## Фаза 3: MVP разработка (когда начнётся код)

- [ ] Auth + профиль + **привязка к адресу** + роли.
- [ ] Главная: новости, блок быстрых действий, активные голосования и заявки (read-only агрегаты).
- [ ] Модуль **заявок** (CRUD, статусы, уведомления ответственным).
- [ ] Модуль **голосований** (участие только верифицированных, подсчёт, архив).
- [ ] **Доска объявлений** по категориям.
- [ ] **Упрощённый форум/темы** (MVP без полного клона Threads).
- [ ] **Анонимные обращения** + экран модератора.
- [ ] **Счётчики**: минимум — ввод показаний и история; начисления — если есть источник данных, иначе заглушка/ручной ввод админом.
